Browser to wheel

The ESP32 serves the controller page, translates commands into wheel-speed targets, and closes both speed loops with Hall feedback.

Browser protocol

Session and drive fields

The ESP32 serves the page at 192.168.4.1 on its hotspot and at its assigned IP on eduroam. GET / serves the page. POST /control with X-Drive: 1 opens one active session and returns its token. WebSocket /motion carries URL-encoded text with that token and a strictly increasing seq. x and y range from 0 to 200 with 100 at center. High x means right and high y means forward.

Direct RPM and action codes

Add direct=1, send x=100&y=100, and encode each signed wheel speed as RPM plus 240. left=260&right=220 means +20 and −20 RPM. clear=0 drives or coasts. clear=1 stops or clears a Hall fault. clear=2 enables Hall override. clear=3 requests joystick-release braking.

HTTP fallback, tuning, and OTA

POST /drive accepts the same drive fields as query parameters. POST /tune accepts session, side=l|r, and kp, ki, kd. side=s saves both sets of applied gains. POST /update comes from the OTA tool and carries the raw application image plus hash and authentication headers.

Telemetry and wheel I/O

Status snapshot

left and right are estimated RPM. leftTarget and rightTarget are commanded RPM. The browser computes error as target minus estimate. leftPid and rightPid each contain [P, I, D, throttle]. P, I, and D are PWM percentage points. Throttle is applied PWM percent.

Diagnostics and tuning result

ms is the sample clock. boot and brownout identify restarts. ready, calibrate, fault, override, bench, and max describe drive state. The fault bits are 1 for left Hall, 2 for right Hall, and 4 for PWM. rejection describes a rejected command. leftGains and rightGains contain [Kp, Ki, Kd]. tuneBusy, tuneId, and tuneOk report tuning progress.

ESP32 pins and motor signals

Left wheel PWM / direction / brake / Hall C are GPIO15 / 4 / 12 / 22. Right wheel uses GPIO16 / 23 / 13 / 18. PWM runs at 490 Hz. The ESP32 estimates speed from the Hall signal and runs two independent PID loops. After 350 ms without a fresh motion command it cuts throttle.
